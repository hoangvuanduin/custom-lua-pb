# Plugin Scaffold Design

## Goal

Create the protoc-gen-luau plugin project structure with build tooling. The plugin accepts a `CodeGeneratorRequest` from protoc, parses all 4 proto file descriptors, and writes a `CodeGeneratorResponse` with 4 placeholder `.luau` files. This validates the end-to-end protoc pipeline before any Luau generation logic is added in downstream specs.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Language | Go | Research F001 (high confidence): protogen provides the richest descriptor API, most mature ecosystem, single static binary |
| Framework | Raw protogen only | Simpler than adding Buf protoplugin (Alpha, no tagged releases). Protoplugin can be added later if needed (F002) |
| Location | `custom-lua-pb/protoc-gen-luau/` | Inside the epic repo, not in luau-data-transform |
| generate.sh | Configurable `<proto_dir>` argument | No hardcoded path assumptions |

## Project Structure

```
protoc-gen-luau/
├── go.mod                    # module protoc-gen-luau, Go 1.22+
├── go.sum
├── main.go                   # Entrypoint: protogen.Options{}.Run(generate)
├── generate.go               # Iterate proto files, emit placeholder .luau files
├── generate_test.go          # Golden-file test with captured CodeGeneratorRequest
├── testdata/
│   ├── request.pb            # Serialized CodeGeneratorRequest from real protoc run
│   └── golden/               # Expected placeholder .luau outputs
│       ├── data_types.luau
│       ├── table_schema.luau
│       ├── source_table.luau
│       └── target_table.luau
├── generate.sh               # Build + run protoc with the plugin
└── README.md                 # Build & usage instructions
```

### Dependencies

- `google.golang.org/protobuf` — provides `protogen` package (only runtime dependency)

## Core Logic

### main.go

Minimal entrypoint (~10 lines). Calls `protogen.Options{}.Run(generate)`.

```go
func main() {
    protogen.Options{}.Run(func(plugin *protogen.Plugin) error {
        return generate(plugin)
    })
}
```

### generate.go

The `generate` function:

1. **Iterate files:** Loop over `plugin.Files`. Skip files where `f.Generate` is false (protoc sets this only for files explicitly listed on the command line, not transitive imports like `data_types.proto` imported by `table_schema.proto`).

2. **Map proto filename to Luau filename:**
   - Strip directory prefix (`tables/source_table.proto` -> `source_table.proto`)
   - Replace `.proto` with `.luau`
   - Examples:
     - `data_types.proto` -> `data_types.luau`
     - `table_schema.proto` -> `table_schema.luau`
     - `tables/source_table.proto` -> `source_table.luau`
     - `tables/target_table.proto` -> `target_table.luau`

3. **Emit placeholder:** For each file, call `plugin.NewGeneratedFile(luauFilename, "")` and write:
   ```luau
   --!strict
   -- Generated by protoc-gen-luau from <original_proto_filename>
   return {}
   ```

4. **Logging:** Write diagnostic info to stderr (protoc plugins must not write to stdout except the serialized `CodeGeneratorResponse`).

### generate.sh

```bash
#!/usr/bin/env bash
set -euo pipefail

PROTO_DIR="${1:?Usage: generate.sh <proto_dir> [output_dir]}"
OUTPUT_DIR="${2:-.}"

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
cd "$SCRIPT_DIR"
go build -o protoc-gen-luau .

protoc \
  --plugin=protoc-gen-luau="$SCRIPT_DIR/protoc-gen-luau" \
  "--luau_out=Mdata_types.proto=placeholder/data_types,Mtable_schema.proto=placeholder/table_schema,Mtables/source_table.proto=placeholder/tables/source_table,Mtables/target_table.proto=placeholder/tables/target_table:$OUTPUT_DIR" \
  -I "$PROTO_DIR" \
  data_types.proto table_schema.proto \
  tables/source_table.proto tables/target_table.proto
```

Note: The `M` parameters provide placeholder Go import paths required by the `protogen` framework, which validates Go import paths for all proto files even when generating non-Go output. These values are not used by the Luau code generator.

### generate_test.go

Uses a replay approach (research F008):

1. **Capture step (one-time):** Run protoc with `--descriptor_set_out` or a debug plugin to serialize the `CodeGeneratorRequest` to `testdata/request.pb`.
2. **Test:** Deserialize `request.pb`, construct a `protogen.Plugin`, call `generate()`, compare output file names and content against golden files in `testdata/golden/`.
3. **Benefit:** Tests run without `protoc` installed, making CI simpler and tests reproducible.

## Filename Mapping Rule

| Proto file | Luau output |
|------------|-------------|
| `data_types.proto` | `data_types.luau` |
| `table_schema.proto` | `table_schema.luau` |
| `tables/source_table.proto` | `source_table.luau` |
| `tables/target_table.proto` | `target_table.luau` |

Rule: `filepath.Base(protoFilename)` with `.proto` replaced by `.luau`. This produces flat output regardless of proto directory nesting.

## Acceptance Criteria

1. `go build .` in `protoc-gen-luau/` produces the `protoc-gen-luau` binary
2. `protoc --luau_out=. --plugin=protoc-gen-luau=<path> -I <proto_dir> <proto_files>` succeeds
3. Plugin reads `CodeGeneratorRequest` from stdin, parses all 4 proto files without error
4. Plugin writes `CodeGeneratorResponse` with 4 `.luau` files (correct filenames per mapping table)
5. `generate.sh <proto_dir>` runs the full pipeline end-to-end
6. `go test ./...` passes with golden-file comparison
7. `README.md` documents build prerequisites and usage

## Scope Boundaries

This spec explicitly does NOT include:
- Type definitions, constructors, or JSON codecs (deferred to data-types-codegen)
- snake_case to camelCase conversion logic
- Oneof handling, map field detection, or typeId dispatch tables
- Table schema or fields map generation (deferred to table-schema-codegen)

The scaffold proves: protoc invokes the plugin -> plugin reads all 4 protos -> plugin writes 4 correctly-named .luau placeholder files. That is the contract for downstream specs.
